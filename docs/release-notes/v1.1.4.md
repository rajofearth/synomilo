## Camera permission, app lock arming, call recovery, foreground ringing, talking time

Six defects fixed. Four were regressions introduced by v1.1.3, two of which came from changes that were correct in isolation and incorrect in combination.

### Video calls had no camera

**`android.permission.CAMERA` was never declared in the manifest.** `react-native-webrtc` does not declare it on the app's behalf, and Android denies an undeclared permission with no dialog and no log entry. The request returned "denied", `getUserMedia` deleted the video constraints, and no camera track was ever created. The preview still mounted, because a stream id is returned for an audio-only stream too, so the frame rendered permanently empty with no error surfaced anywhere. Outgoing video was affected identically.

The call screen now logs every local track with its `readyState`, so the two outcomes are distinguishable, and the preview reports "No camera" rather than presenting an empty box.

### The app lock never prompted

v1.1.3 introduced a five-second call hand-off stamp so that accepting a call would not re-prompt for a fingerprint already given. The same stamp was also placed in the `AppState` listener that runs on **every** return to the foreground, so opening the app normally registered a call hand-off, the lock interpreted it as a just-answered call, and suppressed the prompt. The stamp now exists only at the call navigation site. A regression test fails against the released build.

Four further faults in the same rewrite were corrected: a prompt state that could remain set after the OS dismissed the dialog; a memoised handler that captured the first lock episode permanently, preventing a second lock from ever claiming its own prompt; a ref-backed foreground flag that could not re-trigger the prompt effect; and an exemption for an accepted call that carried no deadline, which would have left an install permanently exempt from asking. A gate that arms can no longer present a state offering no way forward, and the "Forgot your PIN" control renders unconditionally.

Settings and the profile previously derived their own description of the lock and could disagree with the gate — reporting "off" where the gate reported "not available", and promising a PIN fallback that was not on screen. A single function now derives the description from the gate's own decision.

One previously documented claim is retracted: biometric re-enrolment does **not** invalidate this app's secure store, because the module passes no `CryptoObject` and therefore holds no key bound to a biometric. Keystore loss surfaces as a reset control, which is recoverable rather than silent.

### A call could not survive a network change

The call screen armed a 25-second connect deadline when the call was answered and never re-armed it, so any later disruption ended a call that had been working. There was also no mechanism to request a fresh path: no `restartIce()`, and `react-native-webrtc` gathers candidates once and never again. A Wi-Fi to cellular handover, a lift, or a tunnel therefore terminated the call, or left the UI reporting "Reconnecting" with no recovery underway.

The deadline now belongs to the phase it expires, so a connected call has no clock running against it. Recovery is real: a native `ConnectivityManager` watcher detects the active network changing under a live call and requests an ICE restart, and an ICE failure triggers the same recovery instead of ending the call. Recovery is bounded at two attempts sharing one window, and the peer is notified exactly once, only after recovery is exhausted. The UI distinguishes connecting, reconnecting and failed, and a call that never connects ends after 25 seconds rather than ringing indefinitely.

### Incoming ringing stopped when the app was foregrounded

v1.1.3 made the notification channel the only permitted source of ringing in the app, in every state. The in-app call screen has no ringing of its own, so foregrounding a call cancelled the notification and with it the only sound available. Ringing is now owned by whichever surface is visible: the in-app overlay rings while the app is in the foreground, the notification channel rings while it is not, and control transfers in both directions without a gap.

Two further causes of intermittent silence were addressed. The device ringtone was accepted on the basis of being non-empty, so a URI that could not actually be opened — a cloud or carrier provider, or a revoked default — produced a permanently silent ring that no later change could repair, because Android notification channels are immutable once created. Ringtone playability is now verified before use, and the channel id moved to `incoming_call_v5` so existing installs receive the corrected configuration. Separately, ending a call reset the audio mode unconditionally, which suppresses the ringer for the next incoming call on many devices; audio is now released only by the component that acquired it.

### Audio

Returning to the foreground ran the same teardown as ending a call, so a live call dropped out of voice-call mode. A live call retains its audio route, and only a call that has actually ended releases it.

Bluetooth and wired headsets were ignored for the duration of every call because the earpiece was forced at setup. An active external device is now preferred, with the earpiece as fallback; the in-call speaker toggle is unchanged.

### ICE candidates queued before the remote description

Candidates arriving before the remote description was set were flushed only on the calling side. The answering side never received an answer, so every early candidate remained queued permanently, and Convex deletes signals as they are consumed, so none were ever redelivered. This accounts for calls that connected inconsistently. The queue is now drained on both paths, and a signal that fails is no longer consumed.

### Talking time reported 275 hours

One call row carried a `createdAt` eleven days before its `endedAt`. It had been left `active` by a terminated application, and the cleanup sweep that eventually closed it recorded the time it observed as the call's end, so the row's duration measured how long it sat in the database rather than any conversation. The reporting screen was formatting an accurate sum of an untrue record.

Talking time is now counted only for a call that was answered and then ended by hangup within the window a conversation can physically last. A record whose end was never observed contributes nothing, and is reported as unknown rather than as zero. Existing rows are corrected without a migration, because a terminal row is never rewritten.

### Known limitation

Calls are configured with STUN only and have no TURN relay, so connectivity cannot be established behind symmetric NAT or on networks that block UDP. TURN raises the probability that a call connects and does not affect the stability of a call once established. It requires a relay endpoint and a shared secret, and is not configured in this release.
