## Corrected version identity

A release-only change carrying the correct `versionName`.

### The problem
v1.1.2 shipped with `versionName "1.1.1"` still set in `android/app/build.gradle`. The updater compares the published version against the version the installed APK reports through `DeviceInfo.getVersion()`, which reads that field. An APK identifying as 1.1.1 while 1.1.2 was published would have been offered 1.1.2 indefinitely, on every launch, with no way to reach a current state.

### The fix
`versionCode` is now 13 and `versionName` is `1.1.3`.

### Also
`AppConstants.versionNumber` had drifted to `1.0.7` while the app was at v1.1.1, and was read by nothing. It now matches the release and documents that the installed version is read from the APK at runtime, which is the only value that cannot drift from what shipped.

All call, theme, notification and app lock changes are as documented in the v1.1.2 notes.
