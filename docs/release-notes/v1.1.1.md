## App lock can no longer lock you out on a fresh install

Fixes the one serious flaw in v1.1.0.

### The problem
The app lock's security rule was "an unreadable secure store is never reported as lock off" — correct for someone who *has* a lock, so a broken keystore cannot silently drop the gate. But on a **fresh install where the lock was never enabled**, the same rule bricked the app: the store threw, the app concluded it must be locked, and showed a recovery-only screen with no lock to recover from. An unreadable store is common and often innocent — no device lock screen set, an OEM Keystore quirk, or a restored `/data` partition.

### The fix
A plaintext, non-secret marker records whether this install *ever* had the lock turned on. It lives in ordinary `AsyncStorage`, so it is readable exactly when the keystore is not, and it holds no secret — just the fact that a lock was configured.

- Marker present → locked-by-default, unchanged. A user with a real lock is still never silently unlocked.
- Marker absent → the lock was never enabled, so it stays off and the app runs normally.

The marker is written only *after* the PIN verifier and the enabled flag are both confirmed, so it can never claim a lock exists when none was set up.
