## Call ringing fixed, live theme switching, media polish

All four call defects were reproduced against a real web-to-phone call.

### Calls
- **Ringtone never played.** The channel pointed at the *device* ringtone (`content://settings/system/ringtone`), silent on any phone set to None, while `res/raw/ringtone.wav` shipped in the repo referenced by nothing. Now the bundled asset is the channel sound, and the channel id moved to `incoming_call_v3` — Android channels are **immutable**, so editing the JS alone could never have fixed it.
- **The notification survived a decline.** Notifee only attaches the notification's extras bundle when a `mainComponent` is set; a bare full-screen intent has none. `IncomingCallActivity` launched with zero extras, so the caller name read "unknown" **and the callId was null** — meaning `App.tsx` dropped the decline entirely and the call stayed ringing server-side forever. The ring screen now recovers its payload from the posted notification.
- **Foreground calls went mute.** The foreground path returned early and posted no notification at all, so there was no channel sound and no vibration. Foreground and background now share one ring path.
- `FOREGROUND_SERVICE_PHONE_CALL` and `MANAGE_OWN_CALLS` were **not** in the merged manifest despite a comment claiming they were — that throws on Android 14+.
- Accept no longer fails with *"You are already in a call"*: an abandoned `active` row used to block every future answer, because `.first()` returned the oldest match. Stale rows are now closed out automatically.

### Calls tab was empty
A regression: `calls.history` returns `{ calls, hasMore, cursor }` but the screen still treated it as an array.

### Theme now follows the device live
Two independent `useColorScheme()` readers — Paper repainted from one snapshot, the navigation container from another — and the navigation theme was React Navigation's blue/red defaults, which never change with the scheme. `src/theme/useAppTheme.ts` is now the single source of truth.

### Media
Video cells were a boxy empty placeholder; they are now a 16:9 cell derived from the bubble geometry with a composed monochrome poster and a duration chip. The viewer's floating white pill is now an edge-anchored control band.

### Performance
`renderItem` depended on `messages`, so **every message re-rendered every visible bubble**. The single thing it needed — the day separator — is now precomputed into a Set.

Android 14+ full-screen-intent permission is now requested once.
