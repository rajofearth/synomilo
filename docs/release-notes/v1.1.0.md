## Biometric app lock, with PIN fallback

The whole app is now gated: biometric primary (fingerprint, falling back to face, then the device credential), with a real PIN fallback, enforced on every app open.

### What is — and is not — stored
- **No biometric data is stored, and none could be.** Fingerprint and face templates are never exposed to an app; they live in the TEE/StrongBox and are not readable by any process. The module passes no `CryptoObject`, so the app holds neither a template nor a key handle — only the enum saying which method matched.
- **The PIN is stored only as a salted PBKDF2-HMAC-SHA256 hash**, 600k iterations, in `EncryptedSharedPreferences` under a non-exportable `AndroidKeyStore` key. The PIN is never written and no read method can return it. The PIN *length* is stored as a count, not a value.
- **`FLAG_SECURE`** is applied natively on host resume, so the app cannot be screenshotted or captured into the app-switcher snapshot.

### Session token moved out of plaintext
The token now lives in AES-256-GCM encrypted storage, migrating on first read: write, read back, compare, and only then delete the plaintext copy. An install that has already migrated is never logged out.

### It cannot brick the install
An unreadable store is treated as locked-by-default, never as "lock off". Forgot the PIN signs you out and clears the lock state. A wrong PIN backs off exponentially with a visible countdown and no terminal state. A PIN pad never covers a live call.

### Also fixed in this release
Three build-breaking defects in the first pass: a `FLAG_SECURE` hook on an RN lifecycle callback removed in 0.81 (so the flag was **never actually applied on any device**), two constructor arity errors in `SecureStoreModule`, and a missing `USE_BIOMETRIC` manifest permission — which would have made the biometric path return `permissionMissing` on every device.

> **Known issue, fixed in v1.1.1:** on a fresh install where the lock was never enabled, an unreadable keystore could leave the app stuck on a recovery-only screen. v1.1.1 adds a plaintext marker so a never-configured install is never gated.
